一、什么是工具调用

1.1 为什么需要工具调用

大语言模型（LLM）本身有以下局限：

局限 说明 示例
知识截止 训练数据有时间截止点 不知道今天的天气
无法计算 只能近似推理，不能精确计算 算不准 12345 × 67890
无法操作 只能生成文本，不能执行操作 不能帮你发邮件、查数据库

工具调用（Tool Calling） 就是让模型能够”调用外部工具”来弥补这些局限。

六、Pydantic Schema 定义工具参数

6.1 为什么需要 args_schema

当工具的参数比较复杂时（需要精确控制类型、描述、默认值、枚举等），用 Pydantic BaseModel 定义 args_schema 是最强大的方式。

优势：

  • 精确控制每个参数的类型、描述、默认值
  • 支持枚举（Literal）、嵌套对象等复杂类型
  • 类型安全，IDE 自动补全
  • schema 自动生成，无需手写 JSON

七、JSON Schema 定义工具参数

7.1 为什么用 JSON Schema

除了 Pydantic Model，还可以直接用 JSON Schema 字典 定义参数。适用于：

  • 不想引入 Pydantic 依赖
  • 已有现成的 JSON Schema
  • 需要更灵活地控制 schema 结构
  • 从外部 API 文档复制的 schema

7.2 JSON Schema 基础结构

JSON Schema 与 Pydantic 的对应关系：

JSON Schema Pydantic 等价 说明
{"type": "string"} city: str 字符串类型
{"type": "integer"} count: int 整数类型
{"enum": ["a", "b"]} Literal["a", "b"] 枚举
{"default": "xxx"} Field(default="xxx") 默认值
"required": ["city"] 无 default 的字段 必填参数
{"description": "xxx"} Field(description="xxx") 参数描述

九、常见问题

Q1：bind_tools 传了 tools 参数到 init_chat_model 会怎样？

tools 不是 init_chat_model 的参数，应通过 bind_tools() 绑定。

Q2：模型返回了 tool_calls 但没有执行工具？

这是正常行为。bind_tools() 只是让模型”知道”有工具可用，模型会返回调用请求（tool_calls），但 不会自动执行。需要开发者手动执行或使用 Agent。

Q3：@tool 没有 docstring 会报错吗？

  • **不使用 @tool**：docstring 被视为普通文本作为 description，不报错
  • **使用 @tool**：如果没有 docstring 也没有 description 参数，会抛出 ValueError: Function must have a docstring if description not provided.

Q6：convert_to_openai_tool 有什么用？

它是调试利器。当你不确定”模型到底看到了什么工具描述”时，可以直接调用它来查看生成的 schema，帮你排查工具描述不准确、参数类型不对等问题。
