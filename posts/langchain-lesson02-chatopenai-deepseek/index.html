一、核心原理：为什么 ChatOpenAI 能调 DeepSeek

DeepSeek 的 API 完全兼容 OpenAI 的 /v1/chat/completions 协议：请求体格式、响应体格式、鉴权方式（Authorization: Bearer sk-xxx）都一致，唯一不同的是服务器地址。

所以只要把 ChatOpenAI 的请求地址从 https://api.openai.com/v1 换成 DeepSeek 的地址，就能直接复用：

同理，这个方法也适用于任何 OpenAI 兼容的服务：通义千问、Kimi、智谱、SiliconFlow、Ollama、vLLM、One-API 等。

9.2 base_url 与 api_base 的区别

这是新手最常踩的坑：

类 参数名 是否要带 /v1 示例
ChatOpenAI base_url 要带 https://api.deepseek.com/v1
ChatDeepSeek api_base 不带 https://api.deepseek.com

原因： ChatOpenAI 内部只拼 /chat/completions，路径版本号需要你提供；而 ChatDeepSeek 内部会自动补 /v1。

若地址写错，通常报 404 Not Found。

十、与 ChatDeepSeek 方案对比

对比项 本篇：ChatOpenAI 上篇：ChatDeepSeek
需装依赖 langchain-openai langchain-deepseek
地址参数 base_url（带 /v1） api_base（不带 /v1）

选择建议：

  • 想一套代码兼容多家模型、或走 One-API/自建网关 → ChatOpenAI
  • 要用 deepseek-reasoner 的推理链等专属能力 → ChatDeepSeek

十一、常见问题

11.1 404 Not Found

原因： base_url 缺少 /v1，或多写了 /chat/completions。

11.2 模型名不存在

deepseek-v4-flash 需要和你所用平台的实际模型 ID 完全一致，否则报 Model Not Exist。

常见可用值：deepseek-chat、deepseek-reasoner。若走第三方网关，请查该网关的模型列表。

11.3 AuthenticationError: Invalid API key

原因： .env 未被找到，或密钥本身失效，或 OPENAI_API_KEY 配置错误。

排查步骤：

常见错误：

  1. .env 里只配了 DEEPSEEK_*，没配 OPENAI_*

    • 解决：添加 OPENAI_API_KEY 和 OPENAI_BASE_URL

  2. OPENAI_API_KEY 是无效的旧 Key

    • 解决：更新为有效的 DeepSeek Key

  3. OPENAI_BASE_URL 缺少 /v1

    • 解决：改为 https://api.deepseek.com/v1

load_dotenv() 默认从当前工作目录逐级向上查找 .env。
若在项目根目录运行 python rs/lesson02/test01.py，可能找不到 lesson02 下的 .env。
