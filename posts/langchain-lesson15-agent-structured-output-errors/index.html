一、为什么需要错误处理

1.1 模型输出的不确定性

受限于模型能力，大模型输出的内容可能并不符合格式要求。例如：

  • 使用 Union[ContactInfo, EventInfo] 时，模型可能同时返回两种结构（而 Union 期望只返回一种）
  • 模型返回的字段类型不匹配（如要求 int 但返回了字符串）
  • 模型遗漏了必填字段

这些情况都会导致结构化输出失败，需要有机制来处理这些错误。

三、策略一：handle_errors=True（默认）

3.1 工作原理

handle_errors=True 是 LangChain 的默认方式：

  1. 捕获所有异常
  2. 使用 LangChain 内置的、信息明确的错误消息模板提示模型重试
  3. 确保最终能得到符合预定格式的有效数据

四、策略二：handle_errors=False（关闭重试）

4.1 工作原理

handle_errors=False 关闭自动重试机制：

  • 任何异常都会直接抛出
  • 中断程序运行
  • 适用于调试阶段，需要快速发现问题

4.2 完整代码

注意：handle_errors=False 时如果模型恰好只返回一个 tool_call，程序正常运行。只有当模型返回多个或格式错误时才会中断。

六、策略四：handle_errors=异常类型元组

6.1 工作原理

传入异常类型或异常类型元组时：

  1. 仅捕获指定类型的异常并进行重试
  2. 其他异常直接抛出，中断程序
  3. 适用于需要精准控制，只对特定错误进行重试的场景

6.2 两种内置异常详解

异常类型 触发条件 典型场景
MultipleStructuredOutputsError 返回的 tool_calls 数量 > 1 Union[A, B] 时模型同时返回了 A 和 B
StructuredOutputValidationError 输出不符合 Schema 要求 字段类型错误、缺少必填字段、枚举值不匹配

七、策略五：handle_errors=自定义函数

7.1 工作原理

传入一个可调用函数时：

  1. 捕获所有异常
  2. 将异常对象传给自定义函数
  3. 函数返回一个字符串作为错误消息
  4. 该消息被用作 ToolMessage 内容，提示模型重试
  5. 灵活性最高，可根据不同异常类型返回差异化的提示信息

十、常见问题

Q1：handle_errors=True 和不设置 handle_errors 有区别吗？

没有区别。True 就是默认值。

Q2：自定义函数必须返回什么？

必须返回一个字符串，该字符串会作为 ToolMessage 的内容传给模型，提示模型修正输出。

Q3：handle_errors=False 时如何自己处理异常？

Q4：异常类型元组中可以放非结构化输出相关的异常吗？

可以，但通常没有意义。只有 MultipleStructuredOutputsError 和 StructuredOutputValidationError 会在结构化输出过程中被抛出。放其他异常类型不会报错，但也不会被触发。

Q5：自定义函数中的 print 有什么用？

用于调试和日志记录。在错误发生时，可以在控制台输出错误详情，帮助开发者了解发生了什么：

Q6：重试次数有限制吗？

LangChain 内部有最大重试次数限制（默认通常为 3 次）。如果模型多次重试后仍然无法生成正确的结构化输出，最终会抛出异常。
