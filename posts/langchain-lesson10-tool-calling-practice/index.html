一、Pydantic Schema 定义复杂参数

1.1 为什么需要 Pydantic Schema

当工具参数比较复杂时（多个参数、不同类型、默认值、枚举等），使用 Pydantic BaseModel 定义 args_schema 是最佳实践：

优势 说明
类型安全 IDE 自动补全，编译时检查
精确控制 每个参数的类型、描述、默认值
支持复杂类型 Literal、Optional、嵌套对象
自动生成 Schema 无需手写 JSON

5.2 手动 vs Agent 对比

对比维度 手动调用（bind_tools） Agent 自动调用（create_agent）
代码复杂度 高（需要写循环、判断、追加消息） 低（一行 invoke）

自定义逻辑 容易（可加日志、重试、过滤） 较难
适用场景 需要精细控制、特殊逻辑 日常开发、快速原型

Q1：Pydantic Schema 中的 bool 类型如何工作？

模型会根据用户的问题推断布尔值：

用户问题 模型推断的 if_forecast
“杭州天气怎么样？” False
“杭州天气怎么样？明天呢？” True
“杭州今天和明天的天气” True

是的，最终结果一样。区别在于：

Q6：多工具调用时，模型如何决定调用哪些工具？

模型根据以下信息决定：

  1. 工具描述（description）：告诉模型这个工具能做什么
  2. 参数描述（Args）：告诉模型需要什么参数
  3. 用户问题：模型分析用户意图，匹配最合适的工具
