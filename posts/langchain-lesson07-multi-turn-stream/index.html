LangSmith 可观测性配置

强烈建议一开始就接上 LangSmith。 不接的话，调试多轮对话就是猜——你看不到实际发给模型的完整消息列表，不知道每轮消耗了多少 token，也无法回溯某轮对话为什么回答错误。

什么是 LangSmith

LangSmith 是 LangChain 官方提供的可观测性平台（Observability Platform），专门用于追踪、调试和评估 LLM 应用。

它的核心价值：

能力 说明
调用追踪（Tracing） 自动记录每一次模型调用的完整输入/输出，包括消息列表、参数、耗时
Token 监控 查看每次调用的 token 消耗和费用
错误排查 报错时可以看到完整的上下文，包括传给模型的所有消息
性能分析 每步耗时可视化，快速定位慢在哪
评估与反馈 收集用户反馈（👍/👎），构建评估数据集

关键特性：代码零改动。 只需配置环境变量，所有 LangChain 调用自动上报到 LangSmith。

二、多轮对话：让模型记住上下文

2.1 为什么需要消息列表

大语言模型本身是无状态的——它不会自动记住之前的对话。每次调用 API，都需要把完整的对话历史作为参数传入。

关键在于：每次调用都要带上之前所有的消息。

三、历史记忆管理：控制上下文长度

3.1 为什么需要裁剪历史

随着对话轮数增加，消息列表会越来越长，带来两个问题：

问题 说明
Token 超限 模型有上下文窗口限制（如 64K tokens），超出后报错
成本增加 API 按 token 计费，历史越长费用越高
性能下降 输入越长，推理速度越慢

解决方案：只保留最近的 N 轮对话，丢弃更早的历史。

五、Unicode 字符清理

5.1 问题来源

在多轮流式输出场景中，模型偶尔会返回包含 Unicode 代理字符（surrogate characters） 的内容。这些字符单独存在于消息历史中时，在下一轮调用 API 进行 JSON 序列化时会报错：

这个错误通常在对话进行到一定轮数后突然出现，因为之前某轮回复中的无效字符被存入了消息列表。

5.2 解决方案

在将 AI 回复追加到消息列表前，清理掉无效的 Unicode 字符：

原理：

  1. .encode('utf-8', errors='ignore') — 编码为 UTF-8 字节流，遇到无法编码的字符直接跳过
  2. .decode('utf-8') — 将干净的字节流解码回字符串

七、常见问题

Q1: 为什么不直接用 model.invoke() 而要 model.stream()？

invoke() 需要等模型生成完所有内容后才返回，如果回复较长，用户可能要等几秒甚至十几秒才看到输出。stream() 是逐 token 返回，用户可以立即看到第一个字，体验更流畅。

Q2: keep_recent_messages 中为什么传给模型的是裁剪后的，但 messages 保留完整的？

这样设计的好处：

  • 传给模型的是裁剪后的，节省 token 和成本
  • 本地保留的是完整的，如果需要可以回溯或重新裁剪
  • 如果未来想换一种裁剪策略，原始数据还在

Q3: max_pairs 设为多少合适？

场景 推荐值 说明
简单问答 2-3 轮 成本低，够用
一般聊天 5-10 轮 平衡记忆和成本
长文写作/编程 15-20 轮 需要更多上下文
长对话场景 考虑摘要策略 单纯保留 N 轮可能不够

Q4: 为什么 print 要用 end="" 和 flush=True？

  • end="" — 默认 print 会在末尾加换行符 \n，流式输出不需要换行
  • flush=True — Python 的输出默认有缓冲区，flush=True 强制立即显示，否则可能要等缓冲区满了才一次性输出，失去”逐字显示”的效果

Q5: 除了 errors='ignore'，还有其他处理方式吗？

推荐使用 ignore，因为代理字符本身没有意义，直接丢弃即可。

Q6: 配置了 LangSmith 但看不到追踪记录？

排查步骤：

  1. 确认 .env 文件位置 — 必须在代码运行目录或其父目录中
  2. 确认 load_dotenv() 已调用 — 且在 model.invoke() 之前
  3. 确认 LANGSMITH_TRACING=true — 拼写正确，没有多余空格
  4. 确认 API Key 有效 — 登录 smith.langchain.com 检查 Key 是否存在
  5. 确认 langsmith 包已安装 — pip install langsmith
  6. 检查网络 — 确保能访问 https://api.smith.langchain.com

快速验证：

Q7: LangSmith 会影响模型调用速度吗？

影响极小。LangSmith 的追踪是异步上报的——它在后台将调用数据发送到 LangSmith 服务器，不会阻塞你的主程序。实际延迟增加通常在 10-50ms 以内，相对于模型推理时间（通常 1-10 秒）可以忽略。
