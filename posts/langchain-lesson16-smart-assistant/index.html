三、第一阶段 — 工具定义

3.1 @tool 装饰器机制

所有工具都使用统一的装饰器模式：

关键要素

要素 说明
parse_docstring=True 自动从 docstring 解析工具描述和参数描述，无需额外写 description
类型注解 函数签名中的类型注解（如 city: str）自动提取为工具的参数 schema
docstring 格式 遵循 Google 风格（Args: / Returns:），parse_docstring=True 才能正确解析
返回值 工具必须返回字符串，Agent 会将返回值传递给大模型作为上下文

为什么 docstring 如此重要？

大模型通过工具的 描述信息 来决定何时调用哪个工具。docstring 的质量直接决定了工具被调用的准确率：

3.2 工具一：天气查询

最简单的工具形式 — 单参数、字典查询、默认值兜底。

设计要点：

要点 说明
dict.get(key, default) 预定义城市返回固定数据，其他城市返回默认天气，不会报错
单参数设计 只需一个 city，降低模型调用出错的概率
模拟数据 硬编码模拟真实 API，实际项目中可替换为真实天气 API
返回格式丰富 包含温度、天气、湿度、风力，便于模型组织回答

eval() 的三层防护：

白名单机制 allowed_names 只允许使用预定义的数学函数和模块
异常捕获 try/except 防止非法表达式导致程序崩溃

3.5 工具四：货币转换

引入多参数设计 — 模型需要同时正确推断多个参数的类型和值。

USD 中转法

只需维护一张「各货币对 USD」的汇率表，就能实现任意两种货币之间的转换。

多参数工具的特点

要点 说明
三个参数 amount（金额）、from_currency（源货币）、to_currency（目标货币）
混合类型 同时包含 float 和 str，模型需要正确推断每个参数的类型
大小写容错 .upper() 统一转换，"cny" 和 "CNY" 都能正确处理
非法检测 不支持的货币返回友好错误信息和可用货币列表

四、第二阶段 — 创建 Agent 并测试

工具定义完成后，需要创建 Agent 来「编排」这些工具，让大模型自动决定何时调用哪个工具。

4.1 创建 Agent

create_agent 参数说明

参数 类型 说明
model BaseChatModel 聊天模型实例
tools list[BaseTool] 工具列表，Agent 可以调用的所有工具
system_prompt SystemMessage 系统提示词，定义 Agent 的角色和行为规范

SystemMessage 的三重作用

  1. 你是谁 — 多功能智能助手
  2. 你能做什么 — 列出五大功能
  3. 怎么做 — 根据问题选择工具，支持组合使用

返回值 字典，包含完整的消息链
获取回答 result["messages"][-1].content 取最后一条消息

4.4 过程式的特点

到此为止，我们实现了一个 过程式 的 Agent 应用：

优点：简单直接，适合测试和演示

不足：

  • 每次调用都是独立的，没有上下文记忆
  • 不支持多轮对话（问”那上海呢？”Agent 不知道你在问天气）
  • 不可复用，修改需要改源码

5.2 chat() 方法 — 多轮对话的核心

多轮对话如何工作？

关键点：每次 invoke 后，self.messages 被更新为完整的消息链（包含系统消息、工具调用、工具结果等），这样下一轮对话时 Agent 能看到所有历史上下文。

5.3 reset() 方法 — 重置对话

清空消息列表，下次 chat() 调用时从零开始，Agent 不再有之前的上下文记忆。
