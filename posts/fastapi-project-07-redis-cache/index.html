一、为什么要加缓存

1.1 没有缓存时

问题：

  • 新闻分类：10 个用户请求 → 查 10 次数据库（数据完全一样）
  • 热门新闻：100 个用户看同一条 → 查 100 次数据库
  • 响应慢：数据库查询是最慢的环节

1.2 加了缓存后

效果：

  • 第一次请求：查数据库（慢）
  • 后续请求：直接读 Redis（快 10-100 倍）
  • 数据库压力大幅降低

1.3 本模块要实现的功能

缓存对象 Redis Key 过期时间 说明
新闻分类 news:categories 2 小时 分类很少变，缓存久一点
新闻列表 news:list:{分类ID}:{页码}:{条数} 30 分钟 每个分类+分页组合一个 key
新闻详情 news:detail:{新闻ID} 30 分钟 每条新闻一个 key
相关推荐 news:similar:{分类ID}:{新闻ID}:{条数} 30 分钟 同类推荐缓存

二、Redis 基础知识

2.1 Redis 是什么

Redis 是一个内存数据库（数据存在内存里），常用于：

  • 缓存：减轻数据库压力（本项目的用途）
  • 会话存储：存储用户登录状态
  • 消息队列：异步任务处理
  • 排行榜：利用有序集合

2.2 本项目用到的 Redis 命令

命令 作用 Python 对应
GET key 获取值 redis_client.get(key)
SETEX key seconds value 设置值+过期时间 redis_client.setex(key, seconds, value)
DEL key 删除 key redis_client.delete(key)

十、缓存策略总结

10.1 什么数据适合缓存？

数据类型 是否缓存 原因
新闻分类 缓存 2 小时 很少变化
新闻列表 缓存 30 分钟 读多写少
新闻详情 缓存 30 分钟 读多写少
相关推荐 缓存 30 分钟 读多写少
浏览量 不缓存 实时变化
新闻总数 不缓存 count 查询很快
用户数据 不缓存 安全性要求高

10.3 缓存一致性问题

问题： 数据库更新了新闻，但缓存还是旧数据

本项目的处理方式： 靠过期时间自动失效

  • 最多 30 分钟后自动更新
  • 简单粗暴，但有效

十三、常见问题

1. Redis 连接失败

解决： 确认 Redis 服务已启动

2. 缓存的数据和数据库不一致

原因： 缓存还没过期

解决：

  • 等待过期
  • 手动删除：redis-cli DEL news:categories
  • 代码中增加缓存失效逻辑
