一、FastAPI 核心知识点

1.1 什么是 FastAPI

FastAPI 是一个基于 Python 的现代 Web 框架，用于构建 API 接口。

核心特性：

  • 基于标准 Python 类型提示，自动生成 API 文档
  • 异步支持（async/await）
  • 自动数据校验（基于 Pydantic）
  • 高性能（与 NodeJS、Go 相当）

1.2 必须掌握的知识点

知识点 说明 本项目使用场景
路由（Router） 定义 API 接口路径和方法 用户注册、新闻列表等所有接口
路径参数（Path） URL 中的参数，如 /user/123 删除浏览记录 /delete/{history_id}
查询参数（Query） URL 问号后的参数，如 ?page=1 分页、筛选
请求体（Body） POST/PUT 请求的 JSON 数据 注册、登录、修改信息
依赖注入（Depends） 复用代码、共享连接 数据库连接、Token 认证
中间件（Middleware） 请求/响应的预处理 CORS 跨域处理
异常处理（Exception） 统一错误返回格式 全局异常处理器
Pydantic 模型 数据校验和序列化 请求参数校验、响应格式定义
异步编程（async/await） 非阻塞 IO 所有数据库操作

1.3 SQLAlchemy ORM 知识点

知识点 说明 本项目使用场景
DeclarativeBase ORM 基类 所有模型继承
Mapped 类型 类型安全的列定义 Mapped[int]、Mapped[str]
mapped_column 列配置 主键、外键、索引
关系（Relationship） 表关联 用户-收藏、新闻-收藏
查询（select/insert/update/delete） CRUD 操作 所有数据库操作
异步会话（AsyncSession） 异步数据库连接 get_db 依赖

二、项目概述

2.1 项目做什么

这是一个新闻应用后端，提供以下功能：

  1. 用户系统：注册、登录、获取信息、修改信息、修改密码
  2. 新闻浏览：查看分类、新闻列表、新闻详情、相关推荐
  3. 收藏功能：收藏新闻、取消收藏、查看收藏列表
  4. 浏览历史：记录浏览、查看历史、删除记录

分层架构的核心思想

各层职责

层级 职责 为什么单独一层
routers/ 定义 API 接口，接收请求，返回响应 接口逻辑和数据库操作分离，代码更清晰
crud/ 封装数据库操作（增删改查） 复用数据库操作，Router 层不需要写 SQL
models/ 定义数据库表结构（ORM 映射） 表结构集中管理，修改方便
schemas/ 定义请求/响应数据格式 自动校验数据，防止非法数据进入系统
utils/ 通用工具（加密、认证、响应） 复用代码，避免重复实现
config/ 配置文件 配置集中管理，环境切换方便

四、数据库设计

4.1 表结构总览

4.2 表关系详解

1. user（用户表）

存储用户基本信息。

2. user_token（Token 表）

存储用户登录令牌，用于身份认证。

关系说明：

  • user_id 关联 user.id
  • 一个用户可以有多个 Token 记录（但代码中只保留最新的一个）
  • ON DELETE CASCADE：用户删除时，Token 自动删除

3. news_category（新闻分类表）

存储新闻分类信息。

4. news（新闻表）

存储新闻内容。

关系说明：

  • category_id 关联 news_category.id
  • 一个分类可以有多条新闻（1:N）

5. favorite（收藏表）

存储用户收藏的新闻。

关系说明：

  • user_id 关联 user.id
  • news_id 关联 news.id
  • UNIQUE KEY (user_id, news_id)：防止重复收藏
  • 这是 user 和 news 的多对多关系的中间表

6. history（浏览历史表）

存储用户浏览过的新闻。

关系说明：

  • 同样是 user 和 news 的多对多关系
  • 与 favorite 不同：同一用户可以多次浏览同一新闻（更新 view_time）

4.3 表关系总结

关系 类型 说明
user → user_token 1:N 一个用户多个 Token
news_category → news 1:N 一个分类多条新闻
user → favorite 1:N 一个用户多个收藏
news → favorite 1:N 一条新闻多个用户收藏
user → history 1:N 一个用户多条浏览记录
news → history 1:N 一条新闻多条浏览记录

多对多关系：

  • user ↔ news（通过 favorite 表）
  • user ↔ news（通过 history 表）

六、本项目要实现的功能清单

6.1 用户模块

  • 用户注册（密码加密、生成 Token）
  • 用户登录（验证密码、生成 Token）
  • 获取用户信息（Token 认证）
  • 更新用户信息（昵称、头像、性别等）
  • 修改密码（验证旧密码）

6.2 新闻模块

  • 获取新闻分类列表
  • 获取新闻列表（分页、按分类筛选）
  • 获取新闻详情（浏览量 +1、相关推荐）

6.3 收藏模块

  • 检查是否已收藏
  • 添加收藏
  • 取消收藏
  • 获取收藏列表（分页、包含新闻详情）
  • 清空所有收藏

6.4 浏览历史模块

  • 添加浏览记录（重复浏览更新时间）
  • 获取浏览历史列表（分页、包含新闻详情）
  • 删除单条浏览记录
  • 清空所有浏览记录
